# 学习记忆与 Git 记录

本规则负责学习进度、完成时间、记忆巩固和 Git 记录。与通用记忆流程的 Daily/Core 示例冲突时，学习内容按本规则落盘；继续遵守工作区契约的权限、真实证据和目录边界。

## 什么算学完

- 生成卡片只表示“待学习”；发送、打开卡片或开始练习都不是学完。
- 结束练习只表示本次练习收尾。根据真实回答记录 `discussed / practiced / needs-review`，不自动把卡片标成已学，不把结束等同于掌握。
- 用户明确说“这张学完了”，或文件中的 UI 标记为 `status: learned`，才是用户确认已学。Agent 记录该确认，但不替用户操作 `status / feedback`。只说“懂了”、没有回答、退出对话或到达计划时间，不能据此判断学完。
- 通过测验只能支持该次测验范围内的表现。长期掌握需要复习/复测证据，不能靠已学标记或一次正确回答推断。

## 完成时间与历史

记录三种不同时间：卡片创建日期、练习发生时间、用户确认学完时间，不能互相替代。

1. 优先使用本 Session 中明确的确认消息时间、已有练习记录或用户提供的时间。精确时间使用带时区 ISO 8601；只知道日期就原样记录日期并说明精度，不补造时分秒。
2. 卡片 UI 当前只写 `status / feedback`，没有保存点击时间。若只看到 `learned` 而无确认时间，完成时间写 `null`、注明未知；另存实际 `recorded_at`（本次记录时间）。文件修改时间、Git 提交时间、首次发现标记的时间均不是完成时间。
3. 明确完成/取消已学的事件保存在已有 `assessments/` 中，命名 `YYYY-MM-DD-learning-<event-id>.md`。Frontmatter：`type: learning-progress`、`card`（工作区相对路径）、`event`（completed/reopened）、`occurred_at`（已知时间或 null）、`recorded_at`（实际带时区时间）、`session_id`；正文写确认来源、时间精度、相关练习文件、遗留问题和下一步。
4. 同一次确认复用既有事件文件；写之前核对当前 Session、确认来源和已有记录。重复收尾、重复记忆更新、对话确认后又看到同一次 UI 已学标记，不新增副本。只有新的明确完成/重新学习事件才新增文件。
5. 取消已学时保留以前的完成事件，新增 `reopened` 事件。不删除过去的完成时间，不把当前状态反向改写成“从未学过”。重新学习的依据是用户明确说重新学习，或有证据证明同一 UI 标记从 learned 变为 new；仅看到当前 new 不能推断取消。对话中确认学完不会自动改 UI 字段，UI 仍为 new 也不推翻对话中的确认。
6. 没有确认来源或状态变化证据时，不创建进度事件。没有实际回答时不创建空练习记录；用户明确的完成确认可以独立于练习记录存在，但不得由此编造答案或成绩。

## 学习记忆如何更新

- `cards/`：课程内容及用户当前标记；不堆积对话全文，不改原卡的创建日期。
- `assessments/`：真实练习、测验及进度事件的历史事实源；保留用户答案摘要、结果、时间、证据和待解决问题。
- `topics/`：有证据、可复用的新理解和知识连接；单次失误不升级成长期能力缺陷。
- `mistakes/`：同一错误重复出现两次以上再总结长期错因，复习改正后保留历史并标记 resolved。
- `.claude/rules/04-LEARNING-STATE.md`：整体重写当前焦点、近七天摘要、下一步、活跃错题指针；摘要引用真实记录，不把未知完成时间写成今天。
- `.claude/rules/03-USER.md`：只保留用户明确的长期学习目标、节奏和有效教学偏好；单次授权、简单接受和推测不升级为永久偏好。

先保存历史事实，再更新 topic/STATE。部分写入失败逐项保留并说明；本地保存成功、Git 提交成功、远程同步成功是三个独立结果。学习区不另外创建通用 `memory/`、Daily 或 `04-MEMORY.md` 来复制同一套学习事实。

## 什么时候记录到 Git

在一项有实际产物的学习操作明确收尾后处理：生成待学卡片、保存练习/测验、记录完成或重新学习、周/月复盘、或明确调用记忆更新。不要每轮追问都提交，不创建空提交；同一轮相关文件合为一个提交。

1. 先读取本规则、相关历史和当前 Session 产物，完成上述记忆巩固，再检查 Git。
2. 工作区不是 Git 仓库时，正常保留本地学习记录；不自动初始化仓库、创建 GitHub 仓库或新增 remote。需要同步时让用户先明确关联仓库。
3. 若工作区处在更大的仓库内，Git 操作限制在当前工作区和本次相关文件；先检查 diff 和暂存区，不能提交其它工作区、其它 Session 或用户无关改动。暂存区已有无关内容或同一文件混入无法分离的改动时，保留现场，报告阻塞，不自动 stash/reset。
4. 使用显式文件列表 stage；禁止 `git add . / -A / -f`。不提交聊天全文、凭据、运行日志、未经用户授权上传的原始资料；不修改 ignore 规则绕过限制。
5. 提交说明反映学习事件，例如 `learning: 准备营收与利润待学卡片`、`learning: 记录六级听力练习`、`learning: 确认学完营收与利润`、`learning: 重新学习营收与利润`。正文写课程/卡片、真实结果、发生时间与精度、相关记录、未解决问题及下一步；不能只写“更新记忆”，不能把生成卡片写成学完。
6. Git 提交时间仅代表存档时间；提交正文中的完成时间必须来自实际确认记录。无真实进度事件时只描述本次产物，不填完成时间。
7. 只有当前仓库已有 remote、当前分支有明确 upstream，且用户已明确授权该学习工作区自动同步时，才 push 当前分支。无授权/无 upstream 时保留本地 commit，说明尚未同步；不猜远程目标、不新建分支、不切分支、不 force push、不改写历史。
8. 推送冲突、认证失败或网络错误时保留本地文件和 commit；说明同步失败，不回滚学习记录，不宣称已上传。显式调用系统记忆更新时沿用其成功标记协议；已授权推送失败不得返回成功标记。

本规则是 Agent 执行协议，不是后台监听器。定时记忆更新仍需在工作区设置中启用；UI 标记本身不会立刻触发 Agent 或 Git。后续学习收尾/记忆更新读取实际文件后再巩固和提交。
