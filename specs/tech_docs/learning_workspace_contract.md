# 学习工作区契约（v1 评审稿）

状态：评审稿
范围：本地学习工作区的文件结构、事实源、读写权限、应用投影与升级
目标：让用户、UI、任务调度器与不同 Agent Runtime 围绕同一份本地学习资料协作，不产生互相覆盖的第二事实源。

## 1. 核心模型

一个学习工作区是一个用户长期拥有的本地目录。学习内容和学习历史以目录中的 Markdown / 普通文件为事实源；Agent 通过当前 Session 的工作区上下文读写这些文件。MyAgents 负责创建目录、管理工作区身份、调度任务、提供文件访问和把必要字段投影到 UI。

“本地文件是事实源”只适用于学习内容，不意味着应用的所有状态也写入该目录。每类事实仍有唯一 owner：

| 事实 | 权威来源 / owner | 说明 |
|---|---|---|
| 学习卡片、主题、来源、测验、错题、复盘、当前学习状态 | 当前学习工作区中的文件 | Agent 与 UI 均通过工作区文件服务访问；不在 localStorage 或 AppConfig 另存一份内容副本 |
| 工作区路径、项目身份、是否为学习工作区、模板来源标记、当前选中的学习工作区 ID | AppConfig | 这是应用目录索引与选择信息，不是学习内容；当前学习文件仍以该 ID 对应的本地路径为准 |
| 定时任务定义、触发状态与执行记录 | Rust TaskStore | 任务执行可读写工作区文件，但任务元数据不属于工作区文件 |
| 对话 Session 元数据与 transcript | SessionStore | 可记录关联的 workspace path；不复制学习文件内容作为 Session 权威 |
| UI 当前选择、展开、筛选、临时编辑状态 | Renderer 临时状态 | 可丢弃、可重建；不得覆盖文件中的学习内容 |
| Task Center 中最近创建的每日任务引用 | localStorage 的路径到 Task ID 映射 | 仅用于 UI 导航提示；任务内容、执行状态与 workspace path 仍以 TaskStore 为准 |
| 工作区文件搜索索引、文件树缓存、watcher 变更提示 | Rust / Renderer projection | 可从文件重建，不拥有原始内容；重建或延迟不得改变文件 |

新事实若不属于上述类别，落地前先确定具体 owner、scope 和 lifecycle，不以“学习系统”作为一个笼统数据库。

## 2. 标准目录与文件

新建工作区的 v1 基线如下。点文件和空目录占位文件也属于模板内容，应随应用资源一起发布。

```text
learning-workspace/
├── CLAUDE.md
├── INTRODUCTION.md
├── .gitignore
├── .claude/
│   └── rules/
│       ├── 00-WORKSPACE-CONTRACT.md
│       ├── 01-IDENTITY.md
│       ├── 02-SOUL.md
│       ├── 03-USER.md
│       └── 04-LEARNING-STATE.md
├── inbox/                 # 尚未处理的输入
├── sources/               # 已阅读或整理的原始资料
├── cards/                 # 学习卡片
├── topics/                # 稳定主题知识
├── assessments/           # 测验与评估记录
├── mistakes/              # 跨次重复出现的错因总结
├── reviews/
│   ├── weekly/
│   └── monthly/
└── archive/               # 已完成周期的历史归档
```

v1 不要求额外的 `projects/`、`daily/` 复盘目录或数据库。只有在现有文件结构不能清晰表达一种真实产物时，才新增目录或格式。

模板文件负责解释工作区规则与提供可读示例；正式数据应遵守文件命名、Frontmatter 和来源记录约定。示例不能引入看似真实但无来源的统计结论。用户特定资料不得作为通用模板默认值发布。

## 3. 文件格式与可追溯性

- 学习卡片位于 `cards/YYYY-MM-DD-<slug>.md`；日期用于排序，slug 使用小写 ASCII 字母、数字和连字符。
- 测评、周复盘、月复盘使用稳定日期命名（分别为 `YYYY-MM-DD-<topic>.md`、`YYYY-Www.md`、`YYYY-MM.md`）。具体类型字段以模板说明和当前解析器共同维护；格式调整需同步解析器与示例。
- 机器可投影的 Markdown 文件使用 YAML Frontmatter。卡片至少有 `id`、`title`、`category`、`time`、`status`、`feedback`；关联项和来源有值时用 `related`、`source`、`source_url` 表达。
- 内容中的外部事实、数据、引文应带来源，或明确标成假设/示例。Agent 不得为了让卡片显得完整而编造数字、研究结论或来源。
- 历史产物默认追加新文件，不静默改写旧正文。更正旧内容时保留来源和更正意图；UI 字段更新例外见第 5 节。

## 4. 操作读写权限

所有文件读写由工作区文件服务完成，走 Rust/Tauri `cmd_workspace_*` 与 `useWorkspaceFileService(workspacePath)`。Agent 使用 Runtime 对应的工作区指令加载路径；不为读写工作区启动额外 Sidecar，也不把文件写入改走 AppConfig。

| 操作 | 可读 | 可新增 | 可更新 | 禁止 |
|---|---|---|---|---|
| 每日学习 / 新建学习卡 | `04-LEARNING-STATE.md`、近期卡片、相关主题与来源、待处理 inbox | 一张新卡；处理后的来源文件 | 当前状态；被明确吸收的主题页；已处理输入的整理结果 | 批量重写历史卡；消费尚未实际阅读的 inbox 文件；编造来源或数据 |
| 概念讨论 / 深化 | 相关主题、卡片、来源、当前状态 | 有稳定复用价值的新主题页 | 相关主题页中的知识关系、例子与待验证问题 | 将一次性聊天全文复制为长期知识；覆盖无关主题 |
| 测验 / 评估 | 相关主题、卡片、用户指定范围 | 一份带日期的 assessment | 当前状态中的掌握摘要；存在重复模式时更新 mistakes | 把单次失误直接诊断为稳定缺陷；无证据篡改历史测验 |
| 周 / 月复盘 | 对应周期内的卡片、assessment、mistakes、此前状态 | 对应周期的 review | 当前状态的精简摘要；满足归档规则时移动已闭合周期材料 | 越界读取或随意重写长期历史；归档未闭合或用户仍在处理的资料 |
| 导入资料 | 用户指定文件与目标工作区结构 | 原始输入先进入 inbox | 只有完成阅读/分类后才能转入 sources 或提炼主题 | 导入时把资料标成已学习；覆盖同名文件 |
| 用户编辑文件 | 用户可读写工作区内任意其有权限的文件 | 任意 | 任意 | 应用不得通过隐式同步回滚用户修改 |
| 学习 UI 浏览 | 卡片文件及其可投影字段 | 无 | 无 | 把文件内容复制到另一份 UI 数据库作为权威 |
| 学习 UI 标记状态 / 反馈 | 被操作的卡片文件 | 无 | 仅 `status` 与 `feedback` Frontmatter | 改正文、Agent 字段或其他 Frontmatter；CAS 冲突时覆盖 Agent 新版本 |

Agent 不负责创建/删除工作区骨架目录。目录结构由模板创建或由应用的显式“接入已有文件夹”动作补齐。正常学习操作不删除历史文件。归档是移动/保留原文的生命周期操作，不等于清理删除。

## 5. UI 投影与写回

卡片生成、后续练习、持久化边界与尚未实现的记录协议，见 [学习卡片生命周期](./learning_card_lifecycle.md)。其中区分了当前实现与尚未实现的自动保障。

### 5.1 文件读取

学习面板以 AppConfig 中选定的学习工作区路径为根，读取 `cards/` 下符合命名和 Frontmatter 约定的 Markdown 文件，再将可识别字段解析成卡片列表。排序、筛选、列表数量上限和卡片展示均为 projection，不形成第二份内容权威。文件变更通过 workspace watcher 触发刷新；搜索索引同样是可重建投影。

`status`、`feedback` 以外的内容由 Agent/用户维护。最近变更提示是当前面板生命周期内的轻量 watcher 提示，不承诺为永久审计日志。若未来要展示持久历史，必须先定义其 owner 与保留策略。

### 5.2 UI 写回

UI 标记“已学 / 有用 / 跳过”时，只修改卡片 Frontmatter 的 `status` 或 `feedback`。保存必须携带读到的原始内容作为 `expectedContent` 做 compare-and-swap：若文件已被 Agent 或用户改写，UI 刷新最新文件并提示重试，不能把旧快照覆盖回去。UI 更新须保留其它字段、格式和正文。

任何新增 UI 可编辑字段都必须先更新字段 owner 表、解析器、Frontmatter 契约和冲突策略。不要只在 React state 中加一个看起来可编辑但无法持久化的字段。

### 5.3 当前工作区选择

AppConfig 的项目记录负责标记学习工作区，`activeLearningWorkspaceId` 负责选择当前工作区。只有一个学习工作区时可兼容性地默认使用它；存在多个时必须由用户明确选择，不能静默取列表中的第一个。Task Center、学习讨论和新建学习任务必须绑定该选择对应的 workspace path。已创建任务继续使用其 TaskStore 中固定的 workspace path，切换当前学习工作区不应重定向旧任务。被归档的项目是否仍参与定时执行由任务绑定的 workspace path 决定，而不是 UI 列表是否可见。

## 6. 新建、接入与升级策略

### 新建

- 唯一模板源码为仓库中的 `bundled-workspaces/learning/`，应用构建后只读打包到资源目录。
- 新建时把模板完整复制到一个新目录；复制包含隐藏规则文件和空目录占位文件，不从现存用户工作区反向生成模板。
- 模板源码必须纳入版本控制，并由自动化/测试验证所需文件存在、能够进入应用资源包且新建工作区结构完整。

### 接入已有目录

- 接入是显式用户动作。应用可以补齐标准目录和缺失的学习规则文件，但任何已存在的文件字节都视为用户内容，绝不覆盖。
- 在写入或登记项目前，UI 必须展示所选路径和变更预览，用户确认后才执行；取消或预检失败时不写文件、不改变 AppConfig。
- 预览说明将新增的目录 / 规则文件数量，以及会保留的已有目录 / 文件数量。路径已登记为其它工作区时，明确说明确认后会复用该项目并改归学习区。
- 预检发现目标路径不是普通目录、标准目录路径被文件 / symlink 占用、规则文件路径被目录 / symlink 占用时，整次接入停止，不能先写入无冲突部分。
- 预览后目标发生变化时再次校验；新目录路径若在确认前被占用则停止创建。目录或规则文件以“不存在才创建”的方式加入，不能覆盖并发写入的用户文件。
- 接入不得用通用模板的样例卡、个人目标或示例资料填充已有目录；也不应把用户已有文件移动或重命名。
- 若目录已有自己的 `CLAUDE.md` / `AGENTS.md` / `GEMINI.md`，接入不得覆盖或额外写入另一份根级指令。学习专属约定以 `.claude/rules/00-WORKSPACE-CONTRACT.md` 等独立规则文件加入，依靠 Runtime 现有兼容加载层读取。
- 文件系统根目录、用户主目录和 MyAgents 数据目录本身不能作为学习工作区；symlink 根路径和模板资源目录也不能作为接入目标。

### 后续版本升级

- 已创建/接入的工作区归用户所有。安装新版本时不得自动把新模板覆盖、合并或删除进用户目录。
- v1 不建立自动模板同步机制，也不以模板版本号触发后台迁移。
- 未来若提供“修复/升级工作区”动作，必须由用户显式触发、先展示将新增的文件和冲突列表；只自动创建缺失目录/缺失的独立规则文件。与现有路径同名的文件只报告差异，留给用户比较或手动合并；任何迁移保持幂等并可重复执行。
- 升级不能把旧卡片格式强制重写成新格式。解析器应在兼容期读旧格式；只有经评审定义迁移策略后才可提供显式批量转换。

## 7. Runtime 兼容

工作区契约描述产品层语义，不因 Claude、Codex、Gemini 或内置 Agent 而改变。不同 Runtime 可以有各自的指令文件加载适配器，但只应有一个可核对的学习规则正文，或有自动一致性检查避免规则漂移。新建与接入后必须验证当前 Session 实际读到了学习规则；“文件存在”不等于“Runtime 已加载”。

## 8. 当前实现核对与差距

本节记录编写本稿时核对到的代码事实，后续随实现更新：

| 项目 | 当前实现 | 与本稿的关系 |
|---|---|---|
| 新建模板 | `cmd_create_workspace_from_bundled_template` 完整复制只读资源目录；目录复制跳过 `.git`、`node_modules` 和 symlink | 符合完整复制方向；模板文件必须进入 Git 和打包资源 |
| 接入已有目录 | UI 先调用 `cmd_preview_learning_workspace_seed` 显示路径、变更数量与保留数量；用户确认后才调用 merge-only seed 并登记项目。冲突预检失败不写入 | 符合明确接入、保留用户文件原则；规则加载通过 Runtime workspace instruction adapter |
| 模板升级 | 没有自动同步既有用户目录的路径 | 符合不静默覆盖；以后升级动作必须按显式预览策略设计 |
| 卡片读取 | 学习工作区 Chat 在生成卡片的回复下，按本轮已完成文件编辑或明确文件引用读取 `cards/` 中的实际 Markdown；Task Center 保留卡片汇总 | 学习主路径在当前对话完成，无需返回任务 Tab；普通 Agent Chat 不显示学习控件 |
| 对话内练习 | 卡片的「开始练习」通过当前 Chat 的既有发送入口，携带文件路径和引导问题继续当前 Session | 不创建新的讨论 Session，不切换工作区，不创建任务 |
| 卡片 UI 写回 | 仅 patch `status` / `feedback`，使用 `expectedContent` | 与 UI 受限写权限一致 |
| 工作区选择 | AppConfig 保存 `activeLearningWorkspaceId`；仅有一个时兼容默认使用，多个时由学习页面要求明确选择 | 学习讨论和新建学习任务绑定当前选择的 workspace path；旧任务保持 TaskStore 中已有路径 |
| 最近每日任务提示 | localStorage 按 workspace path 保存 TaskStore task ID，Task Center 读取任务状态 | 仅作为界面引用，不持有任务事实 |
| 最近修改 | watcher 在当前面板记录最多少量近期 Markdown 路径 | 这是临时提示，不是持久审计记录 |

## 9. 验收标准

1. 干净安装的新建工作区包含本稿第 2 节完整基线，包括隐藏规则文件和空目录占位文件；模板变更随 Git 与构建资源发布。
2. 接入已有工作区是可重复的：缺失结构会补齐，已有同路径文件逐字节保持，样例内容不会被塞进用户目录。
3. 对话和定时任务明确绑定 workspace path；多学习工作区不会被 UI 或任务按数组顺序静默选错。
4. 学习 UI 卡片展示随文件变化刷新；状态/反馈写回只改对应 Frontmatter 字段，冲突不能覆盖新文件内容。
5. 重建文件树、搜索索引、UI 状态或 watcher 缓存不会改变学习文件，也不会丢失应用拥有的任务、Session 或项目身份状态。
6. 在每个支持的 Runtime 上，新建和接入工作区后的 Session 都能读取有效学习规则；根级用户指令不会因接入学习模板而丢失。
7. 构建产物中的模板不含个人隐私、密钥、用户专属目标和没有依据的事实性统计。

## 10. 落地顺序

后续按验收标准检查新建/接入工作区在各 Runtime 下是否实际加载规则，并维护模板示例与文件 schema 的一致性。除非某条验收标准确实要求，不增加数据库、云端同步或持久变更时间线。
