# 学习卡片：当前生命周期与待补齐的记录协议

核对日期：2026-10-01。本文区分实际代码行为、教练规则和仍未实现的自动保障。工作区总契约见 [learning_workspace_contract.md](./learning_workspace_contract.md)。

## 1. 卡片是什么

一张卡是一个本地 Markdown 文件，围绕一个知识点提供知识与例子、小行动、引导问题。对话里的彩色卡片是该文件的视图，不是单独保存的内容。

- 文件：`cards/YYYY-MM-DD-<slug>.md`；slug 为小写 ASCII 字母、数字、连字符。
- 模板约定字段：`id`、`title`、`category`、`time`、`date`、`status`、`feedback`、`related`、`source`；可选 `source_url`。
- 正文：知识与例子 → `## 今天的小行动` → `## 引导提问`。
- `status: new / learned` 表示用户是否标记已学，不等于经测验确认掌握。
- `feedback: 空 / useful / skip` 表示用户对内容的反馈，不表示答题结果。再次点击同一反馈可取消；已学也可取消。
- 创建日期属于卡片身份，不应因后来练习修改日期或改名。

解析器目前只做轻量解析：文件名、Frontmatter 边界、非空 title 是展示的主要门槛；其它字段有兼容默认值，日期从文件名读取。它不是完整 YAML/schema 校验器，多行 related 列表尚不能完整解析。缺少强校验不代表文件符合模板契约。

## 2. 哪些事实保存在哪里

| 事实 | 权威位置 | 更新者 |
|---|---|---|
| 卡片知识、练习题、引导问题、来源 | cards 文件 | Agent / 用户 |
| 用户标记已学、内容反馈 | 卡片 Frontmatter status / feedback | 当前学习 UI；Agent保留并读取 |
| 对话过程与后续回答 | 现有 Session 的聊天历史 | 现有聊天系统 |
| 稳定的领悟、补充例子与知识关系 | topics 文件 | Agent，按讨论规则沉淀 |
| 测验结果与当次错误 | assessments 文件 | Agent，执行测验时写入 |
| 重复错误模式 | mistakes 文件 | Agent，重复出现两次以上才独立记录 |
| 当前焦点、近七天摘要、下一步、活跃错题指针 | .claude/rules/04-LEARNING-STATE.md | Agent维护快照 |
| 学习目标、偏好、优先级 | .claude/rules/03-USER.md | 用户与Agent共同维护 |
| 周/月复盘 | reviews/weekly、reviews/monthly | Agent执行复盘时写入 |
| 卡片颜色、布局、列表与筛选 | UI投影 | 应用，不形成另一份知识事实源 |

聊天历史与学习文件各自保存不同事实。聊天里有答案，不代表 topics / assessment / STATE 已经同步更新。

## 3. 已实现的应用行为

### 生成与显示

卡片必须先实际保存成功。学习 Chat 从本轮成功文件编辑、或回复中的明确文件链接/代码引用定位卡片，然后读文件显示。它不会把任意回复猜成已保存卡片，也不会把整个目录中的卡片插入每条回复。

普通 Agent Chat 不显示学习控件。当前消息没有有效卡片、文件丢失或解析失败时回退到原回复。流式回复完成前保留正常文本。

### 开始练习

按钮通过当前 Chat 的已有发送入口，发送卡片路径、标题及引导问题，请教练读取文件并继续练习。使用同一 Session，不创建新任务、不切换到任务 Tab。

按钮本身不修改卡片、不自动标记已学。开始消息携带本次practice_id、Session与记录目标；“结束并记录”通过同一Chat请求教练收尾保存。同一卡片当前挂载期间，重复结束使用同一目标；新一次开始生成新标识。重新打开Session后，教练须核对此前消息复用当前练习目标。

收尾请求本身不是成功保存回执：只有实际落盘的有效记录才展示；未回答不应创建空记录。教练文件写入仍依赖Runtime工具执行，应用尚未实现跨文件事务或内容真实性校验。

### 标记与反馈

UI仅修改 status / feedback，保存前重读文件，携带原内容进行 compare-and-swap。Chat遇到写入失败时再读最新版本并重试一次；再次失败显示错误，不伪装成成功。其它字段与正文保留。

该操作不会直接更新 STATE、topic、assessment，也不意味着立即生成下一张卡。教练在后续读取文件时吸收反馈。

### 文件更新后

已有工作区 watcher 触发界面重新读取。Agent、用户或UI实际改写卡片文件后，正在显示的卡片随之刷新。

同一文件在旧消息里的卡片也显示最新文件内容；原始聊天正文仍是当时的消息。当前没有卡片版本快照或永久变更审计。

任务中心汇总读取选定工作区最新60个符合命名的文件；这是展示上限，历史文件不删除。归档到 archive 后，现有只读 cards 路径的投影不再展示该文件。

## 4. 当前教练规则：依赖Agent执行

以下来自模板的 `.claude/rules/00-WORKSPACE-CONTRACT.md`，不是应用强制事务：

1. 出卡前读取 STATE、最近约7张卡、相关topic与来源；优先消化inbox，完成后迁入sources。
2. 有用户确认的轮换偏好时依偏好安排；周末沿related复习，避免不断开新主题。
3. 一张卡约3–5分钟、一个知识点；回复正文不超过350个汉字，英语练习可保留英文。
4. 写新卡，关联相关内容，维护对应topic并更新STATE；不得在每日出卡时重写旧卡正文。
5. 讨论时一次只问一个问题；结束后把新的领悟追加到topic；了解到目标变化时更新03-USER。
6. 测验结果写assessment；当次错题放在该文件内部，重复两次以上再写独立mistake；已改正只标resolved，不删除。
7. 周/月复盘写对应review并更新STATE，不重写历史review。
8. STATE整体重写，只保留当前焦点、近七天摘要、下一步、活跃错题指针；与dated文件冲突时以文件为准。
9. 不改用户所有的教练身份与风格文件；不替用户填写内容反馈；不新建/删除目录；不编造来源和事实。
10. 年度复盘可归档超过一年且已闭合的卡片，保留文件名，不删除历史。

规则文件属于用户工作区。重编译或安装新App不会覆盖已有规则；仓库模板更新不等于已有课程采用新规则。规则存在也不等于每条Runtime都已加载，需通过实际读取/执行确认。

## 5. “后续内容会记录进去吗”的准确回答

- **继续聊天**：进入Session聊天历史；没有通用的自动“每一轮写回卡片”步骤。明确收尾时，可通过“结束并记录”请求保存本次练习。
- **出现新领悟**：现有提示词要求在讨论结束时写入topic，但结束时机未定义，也没有应用校验这次写入。
- **做测验**：规则要求写assessment；仅点击开始练习并不等于执行测验协议。
- **点击已学/反馈**：确定性地写回卡片Frontmatter；其它学习文件不同时更新。
- **要求补充/纠错卡片**：Agent具备文件编辑能力，但当前契约缺少专门的更正、修订与关联记录协议。
- **在卡片追加“学习记录”等新段落**：文件能保存，但当前UI只解析既定三段；新增二级标题内容不保证显示。不能仅靠往文件末尾追加就承诺用户看得到。

实际商业感知测试已写入卡片、对应topic与STATE。之后开始练习产生了追问，但没有足够证据确认新的练习记录已落到学习文件；不能把开始练习判为完成学习。

## 6. 尚未闭合的边界

| 问题 | 当前缺口 | 应明确的决策 |
|---|---|---|
| 练习何时记账 | 已有收尾请求，尚无模型完成后的强制写入校验 | 文件保存成功后展示；自然收尾未写入时提供重试 |
| 同一卡多次练习 | 当前挂载期间目标稳定，重新打开会话仍靠教练核对消息 | 进一步固化跨重开会话的幂等决策 |
| 学过与掌握 | 只有new/learned；无掌握证据模型 | 用户已学标记与有证据的练习结果分离 |
| 卡片后续可见性 | 已有原卡片下近期记录；全历史分页尚未提供 | 扩展索引与分页，保留真实文件入口 |
| 教练未写文件 | 仅自然语言规则，没有写入完成校验 | 文件确认保存后才称“已记录”，失败可重试 |
| 多文件部分成功 | topic、STATE、assessment不存在统一事务 | 先保存独立记录，派生摘要失败单独报告，可据记录重建 |
| 纠错旧卡 | 不改旧卡的出卡规则与纠错需求未区分 | 显式纠错允许局部修订并记录原因，不静默覆盖原练习证据 |
| 规则升级 | 用户工作区不会自动采用新模板 | 显式比较/合并规则，保留用户自定义 |
| 并发/路径变化 | UI CAS保护范围有限；Agent编辑不是同一写事务 | 同名新文件避免覆盖，移动/归档后的引用策略明确 |

## 7. 已落地的练习记录协议与剩余边界

保持原卡片简短，持续学习历史放在现有assessments目录的独立Markdown里，不新增数据库或目录；使用 `type: practice` 与测验 `type: assessment` 区分。该格式已进入模板契约与UI解析；用户已有规则文件不通过App升级自动覆盖。

一份练习记录至少包含：记录id、卡片工作区相对路径、日期时间、Session/turn关联、用户答案摘要、教练反馈、当前证据支持的结果、待解决问题与下一步。开放讨论不用伪造分数；用户确认结束不代表已经掌握。

收尾协议：

1. 用户点击“结束本次练习”，或教练完成当前一项练习并明确收尾。
2. 先保存独立练习记录，保存失败明确说明；同一练习重复收尾不重复建文件。
3. 有稳定新领悟才追加topic；有重复错误才维护mistake；按规则刷新STATE。
4. 原卡片下就地显示“本次记录”：答案摘要、反馈、未解决问题、下一步与记录文件链接。
5. 用户自行决定是否标记已学；模型不替用户写反馈。
6. 下一次学习读取相关练习记录，针对未解决点复习，不只读取new/learned标签。

当前实现了开始/收尾消息、模板协议、真实文件读取与原卡片下的记录投影。记录必填type、card、practice_id、session_id、recorded_at（带时区）与outcome，支持完整YAML标量解析；非法路径、空正文和未知outcome不展示。同一卡片按practice_id去重，选最新保存时间。

UI读取assessments中命名符合约定的最近120个文件，将与当前卡片关联的记录展示为可展开摘要/正文与原文件链接；这是近期投影，不保证展示全部历史。读取失败提示失败，不把聊天里的“已记录”当事实。

仍待补齐：模型自然收尾未写文件的确定性校验、重新打开会话后的应用级幂等、多文件失败恢复、跨文件索引与全部历史分页。用户标记已学与练习结果仍分离。

## 9. 学习区内容呈现

学习Chat使用共享Markdown的安全解析、链接和图片路径策略，仅覆写引用块/加粗的视觉组件。普通Agent Chat不启用该呈现；卡片与后续学习回复都可使用：

- `> [!CORE]`：核心结论面板。
- `> [!COMPARE]`：对比面板；内部GFM表格按列交替使用蓝/紫底色，颜色不表达好坏。
- `> [!EXAMPLE]`：具体例子面板。
- `**重点**`：课程色文字与轻底色。

未知标记、普通引用、代码块保持原Markdown语义，不猜测正文哪些句子重要。引用块必须在卡片既有三段内部，不另加顶层章节。课程色和内容色通过Theme Token读取，正文保留ink/paper。
